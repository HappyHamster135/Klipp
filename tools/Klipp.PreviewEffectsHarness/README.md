# Native preview FX pixel checks

Run `powershell -NoProfile -ExecutionPolicy Bypass -File tools/Run-PreviewEffectsChecks.ps1` from the repository root on Windows with the app's Windows App Runtime and Visual Studio build tools installed.

The harness links the editor's actual Win2D grade and regional-effect graph. It renders synthetic pixels without opening a window or touching projects or media. Checks cover partial transparency, rectangular and elliptical coverage, unchanged pixels outside the region, effect strength, timing boundaries, original comparison, stacking, saved grades, custom LUTs, and repeated graph disposal.

The runner discovers Visual Studio's Appx task directory when the dotnet SDK cannot locate those build tasks. It applies that path to this command only.

Run the same command with `-VideoRangeChecks` to test real MediaPlayer decoding against synthetic limited-range, full-range, and untagged H.264 videos generated by the app's installed FFmpeg. These checks open an unshown WinUI application, seek while paused, rebuild neutral/FX graphs, and compare copied pixels against FFmpeg. They cover the washed-out preview regression caused by changing decoder output mode after opening a source.

Use `-NotificationChecks` for automated checks of the actual notification windows. These cover native frame removal, foreground preservation, capture exclusion, burst coalescing and dismissal. The popup's own XAML render is exported to a temporary PNG for design inspection without disabling screen-capture exclusion.

Use `-FullscreenNotificationChecks` for interactive QA with a temporary solid-color fullscreen target on a separate UI thread. After the automated checks, follow the two `READY` prompts: activate the fake fullscreen window, then click it at the reported coordinates to verify real input passes through the popup. The actual Klipp WGC monitor backend compares pixels beneath the visible popup to confirm that the card and any placeholder rectangle are absent from captured video. The input fixture stays visible longer than the product duration to allow human/automation coordination; it does not change saved preferences. The target is borderless fullscreen, so this does not claim to test DXGI exclusive presentation. The passive renderer's own bitmap is also exported for design inspection. The target closes automatically, and no user settings, saved media or projects are changed.
