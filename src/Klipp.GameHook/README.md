# D3D11 game capture and notification bridge

This optional x64 DLL hooks the selected window's D3D11 Present path. It copies the clean SDR backbuffer to three private keyed-mutex shared textures **before** drawing a notification. Both recordings and instant clips read those clean textures. The notification is part of the game's displayed frame, so it does not depend on a desktop window being composited above the game. The hook never activates a window or changes fullscreen/display settings.

Enable **Settings → Capture → Exclusive fullscreen · DirectX 11** to opt in. The setting is off by default and applies when capture next starts; restart instant clips to apply it to an existing rolling buffer. Supported targets are selected, same-user, non-elevated x64 D3D11 windows with single-sample SDR BGRA8/RGBA8 discard or flip-discard swapchains. D3D12, Vulkan, OpenGL, HDR, ARM64/32-bit processes, multisampled backbuffers, retained/sequential swapchains and Present1 dirty/scroll presentation are unsupported. Attachment failures fall back to Windows Graphics Capture with the injected notification disabled. Klipp never retries with elevation or attempts to bypass a game's protections.

Cards use the same rounded, borderless artwork as Klipp's desktop notifications: a dark background at approximately 50% opacity, opaque text and icons, and a small DPI-aware inset from the upper-left edge. Cached premultiplied BGRA pixels use `ONE / INV_SRC_ALPHA` blending with opacity-only 160 ms entrance and 140 ms exit fades. Windows reduced-motion preferences disable the fades; high contrast uses the system colors. No extra notification window receives the game's mouse or keyboard input.

The private pipe checks peer process IDs and a random session nonce. Shared NT texture handles are duplicated from the selected process; they have no public name. The render thread never waits for the consumer's keyed mutex or pipe IO. Pipeline state is swapped back after drawing. Resizing keeps the encoder canvas fixed and invalidates notification readiness until the host reads a clean frame from the new texture generation. Notifications are never enabled before that clean-frame handshake.

Stopping capture retains the authenticated bridge for up to 12 seconds so recording-stopped and clip-saved notifications can still appear. Before any WGC fallback or desktop capture, Klipp disables the injected popup and requires acknowledgement of a later clean Present, or confirmation that no popup was drawn. A missing heartbeat disables further popup drawing. If a game completely stops presenting, its last displayed frame can retain a popup; Klipp refuses the capture switch until the game resumes a clean Present or closes instead of assuming those pixels disappeared.

Discard presentation requires the producer to redraw its backbuffer. Klipp rejects preserved buffers rather than restoring old pixels over newly rendered game content. See [DXGI_SWAP_EFFECT](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/ne-dxgi-dxgi_swap_effect). Backbuffer drawing provides a route through true exclusive presentation without a compositor window; testing a DXGI fullscreen request alone does not prove that Windows Fullscreen Optimizations was bypassed.

The DLL stays loaded, with inert pass-through hooks after disconnection, to avoid unloading code while a game thread is executing it. A later capture can reconnect a new authenticated session. Capture includes cursors drawn by the game into its backbuffer; this backend does not composite a separate Windows hardware cursor. This backend requires validation against each supported game and driver; it does not provide universal support for every graphics API or protected title.

An x64 Desktop build runs `build.ps1` and bundles `Klipp.GameHook.dll` and the MinHook license beside Klipp. Building requires the Visual Studio x64 C++ tools and Windows SDK. For a standalone native build, run `powershell -NoProfile -ExecutionPolicy Bypass -File src/Klipp.GameHook/build.ps1` from the repository root.

QA covers discard/flip-discard fullscreen requests, clean capture versus a visible post-present popup, resize recovery, focus retention, stop/grace notifications, rejection of retained/dirty presentation, and a frozen-game fallback barrier that recovers after resume. Actual Klipp instant-clip QA saved three clips while the in-game card was visible. The final 60-second, 900-frame file spanned earlier popups: 4,284,000 decoded pixels in the popup text region had no color deviation above 12 from the clean blue fixture; the maximum deviation was 2. These are disposable fake-game tests, not certification of physical exclusive scanout or real-title compatibility.
